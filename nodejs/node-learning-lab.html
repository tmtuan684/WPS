Interactive Lab · Node.js Fundamentals

Learn Node.js by running it —
right here in the browser.

Node's real APIs (fs, process, require) only exist in an actual terminal, so this lab simulates a small Node runtime in JavaScript: a virtual file system, a fake module registry, a mock process.argv. Every "Run" button below actually executes your code against it.

boot sequence
00 · Orientation

What is Node.js?

Node.js is a JavaScript runtime built on Chrome's V8 engine that runs JS outside the browser — on servers, in CLI tools, even inside desktop apps like VS Code. Same language, a very different set of capabilities.

In the browser

document.querySelector('#app')
window.location.href
fetch('/api/data')

In Node.js

require('fs').readFileSync(...)
process.argv
require('http').createServer(...)
Teaching note Node can't touch the DOM; the browser can't touch the disk. That symmetry is worth stating explicitly in class — it's the single sentence that makes the rest of this module make sense.
How to use this lab Work through the sidebar top to bottom — 01 through 07 follow the same sequence as the fs learning notes (Sync → Callback → Promises, etc). Each section is a self-contained "terminal window" you can experiment in.

05 · Watch it run

Async file reads — why order isn't top-to-bottom

Three files of different sizes are read with fs.readFile() (non-blocking). Predict the order the "Done reading" messages will print, then hit Start and watch real timers confirm it.

Callback style

// small.txt, medium.txt, large.txt
fs.readFile('small.txt', cb);
fs.readFile('medium.txt', cb);
fs.readFile('large.txt', cb);

console.log('Started reading files.');

async/await + Promise.all

await Promise.all([
  fs.readFile('small.txt'),
  fs.readFile('medium.txt'),
  fs.readFile('large.txt'),
]);
// all three run concurrently

Teaching note Have students say their predicted print order out loud before clicking Start. Most predict small → medium → large in program order without realizing "started reading" logs first — this animation makes the non-blocking behavior visible instead of abstract.

07 · Watch it run

A simple HTTP server

This one genuinely can't run in a browser tab — it needs a real terminal listening on a real port. Here's the code, plus a click-through diagram of what happens on each request.

// server.js — run this with: node server.js
const http = require('http');

const server = http.createServer((req, res) => {
  res.statusCode = 200;
  res.setHeader('Content-Type', 'text/plain');
  res.end('Hello World\n');
});

server.listen(3000, '127.0.0.1', () => {
  console.log('Server running at http://127.0.0.1:3000/');
});

Teaching note Node handles this on a single thread using the same non-blocking model as the fs example above — it can start handling a second request before the first one finishes, instead of spawning a new thread per connection. Worth connecting back to Section 05 explicitly.
