01 · Core Concepts

Teach the machine, one small step at a time.

Every model you'll meet, from a single line of best fit to a large language model, learns the same way: guess, measure how wrong the guess was, nudge the parameters to be less wrong, repeat. Try it below.

// gradient descent, live

What "learning" means here

A machine learning model is a function with adjustable knobs (parameters). You don't hand-code the rules — you show the model examples, and an algorithm turns those knobs until the function's output matches reality closely enough. The ball in the widget above is doing exactly that: rolling toward the bottom of a curve that represents error. Bottom of the curve = the knobs are well tuned.

Three ways a model can learn

Supervised

You give the model labeled examples — inputs paired with the correct answer. It learns to map one to the other. Spam detection, price prediction, image classification.

Unsupervised

No labels — the model finds structure on its own: groups, patterns, compressed representations. Customer segmentation, anomaly detection, embeddings.

Reinforcement

An agent takes actions in an environment and learns from reward or penalty signals over time. Game-playing agents, robotics, resource scheduling.

Vocabulary you'll keep bumping into

TermMeans
featureAn input variable the model reads (e.g. square footage, pixel value, word count).
label / targetThe correct answer you want the model to predict.
modelThe function + its current parameters (weights, biases).
loss functionA number that scores how wrong a prediction was. Lower is better.
gradient descentThe nudging algorithm — adjusts parameters in the direction that reduces loss.
learning rateHow big each nudge is. Too big overshoots, too small crawls.
overfittingThe model memorizes training examples instead of learning the general pattern.
train / test splitHolding data back so you can honestly check if the model generalizes.

Build it yourself

1. Linear regression — fitting a line with gradient descent

The model is y = m·x + b. Loss is mean squared error. Each step nudges m and b a little against the slope of that loss.

// one gradient-descent step for y = m*x + b
function trainStep(points, m, b, lr = 0.0003) {
  let dm = 0, db = 0;
  for (const { x, y } of points) {
    const pred = m * x + b;
    const err = pred - y;
    dm += err * x;
    db += err;
  }
  const n = points.length;
  m -= lr * (dm / n) * 2;
  b -= lr * (db / n) * 2;
  return { m, b };
}

2. k-Nearest Neighbors — classify by asking your neighbors

No training loop at all — just distance. To classify a new point, find the k closest labeled points and take a majority vote.

function classify(point, trainSet, k = 3) {
  const dist = (a, b) => Math.hypot(a.x - b.x, a.y - b.y);
  const neighbors = [...trainSet]
    .sort((a, b) => dist(point, a) - dist(point, b))
    .slice(0, k);
  const votes = neighbors.reduce((acc, n) => {
    acc[n.label] = (acc[n.label] || 0) + 1;
    return acc;
  }, {});
  return Object.keys(votes).sort((a, b) => votes[b] - votes[a])[0];
}

3. Perceptron — the smallest possible neuron

One neuron, two inputs, one weight update rule. This is the cell that neural networks are built out of. Here it learns the AND gate.

function trainPerceptron(examples, epochs = 20, lr = 0.1) {
  let w = [Math.random(), Math.random()], bias = Math.random();
  const log = [];
  for (let e = 0; e < epochs; e++) {
    let errors = 0;
    for (const { x, y } of examples) {
      const sum = x[0] * w[0] + x[1] * w[1] + bias;
      const pred = sum >= 0 ? 1 : 0;
      const err = y - pred;
      if (err !== 0) {
        w[0] += lr * err * x[0];
        w[1] += lr * err * x[1];
        bias += lr * err;
        errors++;
      }
    }
    log.push(`epoch ${e + 1}: w=[${w.map(v=>v.toFixed(2))}] bias=${bias.toFixed(2)} errors=${errors}`);
    if (errors === 0) { log.push('converged — stopping early'); break; }
  }
  return log;
}

03 · API & Code

What "deployment" actually looks like

The labs above run a model in the browser. In modern real-world architecture, models are more often trained once in Python (scikit-learn, PyTorch), saved to disk, and served behind a REST API that any web or mobile frontend calls. This can't execute inside this page — it needs a real server — but this is exactly what production code looks like.

1. Python model endpoint — FastAPI + scikit-learn

The server loads an already-trained model artefact once at startup, then just runs inference on each request.

from fastapi import FastAPI
from pydantic import BaseModel
import joblib
import numpy as np

app = FastAPI()
model = joblib.load("house_price_model.pkl")  # trained offline

class PropertyFeatures(BaseModel):
    sqft: float
    bedrooms: int
    age_years: float

@app.post("/predict")
def predict_price(features: PropertyFeatures):
    input_vector = np.array([[features.sqft, features.bedrooms, features.age_years]])
    prediction = model.predict(input_vector)[0]
    return {"status": "success", "predicted_price_usd": round(float(prediction), 2)}

2. Front-end integration — JavaScript / async fetch

The frontend never sees a model or a weight — just a JSON request and a JSON response.

async function fetchHousePricePrediction(sqft, bedrooms, age) {
  try {
    const response = await fetch('https://api.yourdomain.com/predict', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ sqft, bedrooms, age_years: age })
    });
    if (!response.ok) throw new Error('Model server error');
    const result = await response.json();
    console.log(`Estimated Value: $${result.predicted_price_usd}`);
    return result.predicted_price_usd;
  } catch (error) {
    console.error('Inference error:', error);
  }
}

Notice the shape: the Python side owns training and the saved model file; the JS side only ever sees a JSON request/response. That boundary is what "deploying a model" means in practice.

function isSpam(email) {
  const spamWords = ['free', 'winner', 'click here', 'urgent', 'act now', 'limited time'];
  const text = email.toLowerCase();
  const wordHits = spamWords.filter(w => text.includes(w)).length;
  const exclaims = (text.match(/!/g) || []).length;
  return wordHits >= 2 || exclaims >= 3;
}

function sigmoid(z) {
  return 1 / (1 + Math.exp(-z));
}

function willChurn(customer, weights) {
  const z = customer.monthsAsCustomer * weights.monthsAsCustomer +
            customer.monthlySupportTickets * weights.monthlySupportTickets +
            customer.monthlySpend * weights.monthlySpend +
            weights.bias;
  return sigmoid(z) > 0.5;
}

5. "More like this" movie recommender

The job: Your streaming app already represents each title as a short vector (its genre profile — this is a stand-in for the kind of embedding a real recommender or RAG system would use). Given the vector for what someone just watched, find the closest title in the catalog. This is the exact building block behind recommendation engines and semantic search.

Show solution 
function cosineSimilarity(a, b) {
  const dot = a.reduce((sum, v, i) => sum + v * b[i], 0);
  const magA = Math.sqrt(a.reduce((s, v) => s + v * v, 0));
  const magB = Math.sqrt(b.reduce((s, v) => s + v * v, 0));
  return dot / (magA * magB);
}

function recommend(target, catalog) {
  let best = null, bestScore = -Infinity;
  for (const item of catalog) {
    const score = cosineSimilarity(target, item.vector);
    if (score > bestScore) { bestScore = score; best = item.title; }
  }
  return best;
}
